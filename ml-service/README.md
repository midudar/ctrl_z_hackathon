# Инспектор ИИ — ML-часть

Сверяет проектную (ПД), рабочую (РД) и исполнительную (ИД) документацию одного объекта по матрице из 132 параметров
и выдаёт файл ответа: по каждому параметру — метка, значения на стадиях и доказательства (файл, страница, рамка
фрагмента на странице). Вердикт не выносит: `VIOLATION_PRESENT` — это **кандидат** для инспектора.

Подробности про данные, правила и замеры — в [CLAUDE.md](CLAUDE.md). Здесь — как запустить и что лежит в ответе.
**Где лежит:** в командном репозитории `ctrl_z_hackathon` ML-часть — папка `ml-service/` (ветка `ml`). Дальше «папка
ML-части» — это она: все команды запускаются из неё, в ней же `Dockerfile` (контекст сборки — эта папка).
Для команды: полный контракт интеграции (вход, запуск, Docker, поля ответа, интерфейс, протокол) —
[docs/Инспектор_ИИ_ML_для_разработчиков.md](docs/Инспектор_ИИ_ML_для_разработчиков.md); всё для презентации —
[docs/Инспектор_ИИ_ML_для_презентации.md](docs/Инспектор_ИИ_ML_для_презентации.md).

## Запуск

```bash
# локально (Python 3.11+, из папки ML-части — ml-service/)
pip install -r requirements.txt
python -m ml.run OBJ-RECHNIKOV-7-7                    # → out/submission_OBJ-RECHNIKOV-7-7.json
python -m ml.run OBJ-RECHNIKOV-7-7 --out /path/answer.json
python -m ml.run                                       # все объекты из реестра

# Docker (так запускается на стенде). Сначала — архив из GitHub Releases, см. «Чего нет в репозитории»
unzip inspector_ml_assets.zip -d .                    # → out/cache/ и models/easyocr/
docker build -t inspector-ml .
docker run --gpus all \
  -v /path/to/01_ДОКУМЕНТАЦИЯ:/input/docs:ro \
  -v /path/to/data:/input/data:ro \
  -v /path/to/output:/output \
  inspector-ml OBJ-RECHNIKOV-7-7
```

Время на объект на CPU ноутбука (26.09): Новослободская ~1 мин, Тюменская 2–3,5 мин, Речников ~3 мин. OCR во время
прогона **не запускается** — см. «Кэш OCR».

### Что нужно на входе

| Переменная | В образе | Что там |
|---|---|---|
| `INSPECTOR_DOCS` | `/input/docs` | папка документов: `01_ДОКУМЕНТАЦИЯ` из пакета участника; пути файлов — как `relative_path` в реестре |
| `INSPECTOR_DATA` | `/input/data` | `document_manifest.jsonl` (реестр: `file_id`, объект, стадия, раздел, SHA-256), `parameter_catalog_132.jsonl`, `submission_schema.json` — из `02_ФОРМАТ_ДАННЫХ_И_ПРИМЕРЫ/data` |
| `INSPECTOR_OUT` | `/output` | сюда пишутся ответы и отчёты целостности |
| `INSPECTOR_CACHE` | `/app/cache` | кэш распознанных страниц (ключ — SHA-256 файла); по умолчанию `out/cache` |
| `INSPECTOR_MODELS` | `/app/models` | модели EasyOCR (`models/easyocr`) |

Без реестра `document_manifest.jsonl` пайплайн не работает: из него берутся стадия, раздел и `file_id` для ссылок.

В git только код, документация и примеры ответов (1,8 МБ). Остальное — отдельно:

| Что | Где взять | Куда положить | Зачем |
|---|---|---|---|
| `inspector_ml_assets.zip` (92 МБ): кэш распознанных страниц `out/cache/` (970 файлов, 25 МБ) и модели EasyOCR `models/easyocr/` (94 МБ) | **GitHub Releases** этого репозитория (или у Саши) | распаковать **в папку ML-части** (`ml-service/`) | без него **`docker build` падает** на `COPY out/cache/` и `COPY models/easyocr/`; локально без кэша прогон идёт, но теряет значения из сканов |
| Документы объектов и реестр (`01_ДОКУМЕНТАЦИЯ/`, `02_ФОРМАТ_ДАННЫХ_И_ПРИМЕРЫ/data/`) | пакет участника `01_ПАКЕТ_УЧАСТНИКАМ_3_ОБЪЕКТА.zip` от организаторов (8,2 ГБ) | куда угодно, пути — через `INSPECTOR_DOCS` / `INSPECTOR_DATA` | вход пайплайна; данные организаторов в репозиторий не кладём |

| Архивы для Colab (`colab/*_bundle.zip`) и ссылки на них в ноутбуках | собираются скриптами `colab/make_*.py`; ссылку на свой Google Drive вставлять в ноутбук, **не коммитить** | — | только для повторного распознавания сканов; сервису не нужны |

### Кэш OCR — положить в образ обязательно

Почти вся ИД Речникова — сканы (8 324 страницы). Нужные страницы (910: бланки актов и реестры) распознаны заранее
PaddleOCR на GPU Colab, листы ОВ Тюменской — EasyOCR. Результат лежит в `out/cache` (**в git не входит** — архив из
Releases) и копируется в образ (`COPY out/cache/ cache/`). Ключ кэша — SHA-256 файла из реестра: если файлы на стенде те
же, кэш подхватится сам. Без кэша прогон не упадёт, но значения из актов ИД и марки систем на чертежах ОВ пропадут
(страницы читаются только текстовым слоем). Контекст сборки ограничен `.dockerignore` — в папке проекта у ML ~42 ГБ
данных организаторов, без него `docker build` потащил бы их все.

## Что в ответе — `submission_<объект>.json`

Формат — `submission_schema.json` организаторов плюс наши поля (схема лишние поля допускает). Пример (Новослободская,
найденное нарушение):

```json
{
  "parameter_code": "KR-057",
  "location": "Форшахта",
  "violation_label": "VIOLATION_PRESENT",
  "protocol_status": "CRITICAL",
  "criticality": "Критическое (приостановка работ)",
  "pd_value": "рабочая А400",
  "rd_value": "А240",
  "id_value": "А240С",
  "evidence": [
    {"stage": "PD", "file_id": "F0105", "pdf_page_number": 13,
     "bbox_norm": [0.1669, 0.6708, 0.7817, 0.6866], "bbox_source": "text_layer",
     "fragment": "вязанными арматурными каркасами, основная рабочая арматура А400,"},
    {"stage": "RD", "file_id": "F0137", "pdf_page_number": 2, "bbox_norm": [0.7732, 0.856, 0.9919, 0.8638], "...": "..."},
    {"stage": "ID", "file_id": "F0068", "pdf_page_number": 2, "bbox_norm": [0.0665, 0.0742, 0.8804, 0.0861], "...": "..."}
  ]
}
```

| Поле | Что это |
|---|---|
| `parameter_code` | код из матрицы (`KR-057`, `PZ-009`, `IOS4-078`) |
| `location` | где: конструкция («Фундаментная плита»), номер помещения («140») или «Объект» |
| `violation_label` | см. таблицу меток ниже |
| `protocol_status` | статус для протокола: `CRITICAL` / `WARNING` (кандидат по критичности), `OK`, `RD_MISSING` / `PD_MISSING`, `COMPARISON_IMPOSSIBLE` |
| `pd_value`, `rd_value`, `id_value` | значения на стадиях как строки («B30/B35», «1200/1500 мм»); `null` — не найдено |
| `evidence[]` | страницы-доказательства: `stage`, `file_id`, `pdf_page_number` (номер страницы PDF, с 1) |
| `evidence[].bbox_norm` | рамка фрагмента `[x0, y0, x1, y1]` в долях **видимой** страницы, начало — левый верхний угол; CropBox, MediaBox и поворот уже учтены. Подсветка: отрисовать страницу (PDF.js, PyMuPDF — как её видит человек) и умножить на ширину и высоту картинки. `null` — фрагмент не найден, показывать страницу целиком |
| `evidence[].bbox_source` | откуда текст фрагмента: `text_layer` или `ocr` |
| `evidence[].fragment` | обведённый текст — подпись к подсветке |
| `note` | пояснение для инспектора, когда нужно: «в РД нет комплекта ОВ», «значения внутри стадии расходятся …» |

### Метки и как их показывать

| `violation_label` | Смысл | В интерфейсе |
|---|---|---|
| `VIOLATION_PRESENT` | расхождение найдено, есть доказательства | **кандидат в нарушения** — на решение инспектора (подтвердить / отклонить с причиной) |
| `NO_VIOLATION` | сверили — расхождения нет | проверено, нарушений нет |
| `MISSING_DOCUMENT` | нет нужного документа (см. `note`) | не хватает документа |
| `COMPARISON_IMPOSSIBLE` с пустыми `evidence`, `pd_value`, `rd_value` | **для параметра нет извлечения** (заглушка) | «не проверялось системой» — не путать со следующей строкой |
| `COMPARISON_IMPOSSIBLE` с доказательствами | сравнили, но уверенности нет (значение только на одной стадии, сработала страховка) | «нужна ручная проверка», показать `note` |

В ответе всегда все 132 параметра (у Тюменской больше: несколько помещений на параметр ОВ).

### Целостность комплекта — `document_integrity` и `integrity_<объект>.json`

В ответе ключ `document_integrity` — сводка: число файлов, стадии и список дефектов комплекта (`type`, `severity`,
`title`, `file_ids`). Полный отчёт — `integrity_<объект>.json` рядом с ответом. Типы: нечитаемые и пустые файлы,
временные файлы (`.bak`, `~$`, в том числе внутри архивов), PDF без текстового слоя, дубли по SHA-256, дисциплина
есть в ПД, а в РД нет (`DISCIPLINE_MISSING_IN_RD`), исключённые устаревшие редакции, конфликт редакций, шифр в
имени ≠ шифр на титуле, акт ссылается на проект не из пакета. Для протокола (Приложение 2, раздел «статус загрузки»)
это готовый материал.

## Что проверяется сейчас

| Трек | Параметры | Где работает |
|---|---|---|
| ОВ — чертежи по помещениям (`ml/rooms.py`) | IOS4-078, IOS4-079, тёплые полы (`FREE-HEATING-001`) | Тюменская |
| КР — текст общих данных и спецификаций (`ml/concrete.py`) | KR-055 класс бетона (6 конструкций), KR-057 арматура, KR-058/059/061 толщины, KR-060 сечения, PZ-009 отметка 0.000 | все объекты |
| ИД — акты АОСР (`ml/acts.py`) | класс бетона и арматуры из актов в KR-055 / KR-057 (`id_value`, страница акта в `evidence`) | Новослободская (текст), Речников (сканы, PaddleOCR) |
| Пожарные (`ml/fire.py`) | PZ-022 степень огнестойкости, PZ-023 класс конструктивной пожарной опасности | все объекты |
| АР — экспликации помещений (`ml/explication.py`, с 26.09) | PZ-003: помещения, которые появились, исчезли или сменили назначение между ПД и РД; изменённые площади по этажам; итог по объекту | объекты с АР в ПД и РД (Речников; проверено на 8 объектах пилота организаторов) |
| Сталь (`ml/steel.py`, с 26.09) | KR-056: марка стали по элементам (распорная система, фермы, колонны, лестницы…), сравнение по пределу текучести | все объекты |
| Трубы канализации (`ml/pipes.py`, с 26.09) | IOS3-075: материал труб по системам К1, К2…, триггер «чугун / малошумные → ПВХ» | объекты с ВК в РД |
| Комплектность (`ml/submission.py`) | «нет документа», если в РД нет нужного комплекта марок | все объекты |

**Строки PZ-003 в ответе.** Их несколько, различаются полем `location`:
- `«Объект»` — итог: сколько помещений сверено и сумма их площадей в ПД и РД. «Нарушение» — только если в РД площадь
  меньше больше чем на 1% (триггер матрицы «сокращение полезной площади»), иначе «нет нарушения» + справка в `note`;
- номер помещения (`«1.109»`, для коротких номеров с этажом — `«1 этаж, 22»`) — кандидат: помещение появилось,
  исчезло или сменило назначение; что именно — в `note`, значения — в `pd_value` / `rd_value`;
- `«Площади помещений, <этаж>»` — кандидат: у помещений этажа изменились площади, список (крупнейшие первыми) — в `note`.

Это кандидаты для инспектора: изменение может быть согласовано (так же их оценивают и организаторы в своей
пилотной разметке). У доказательств уже есть `bbox_norm` — рамка строки таблицы экспликации.

Остальные параметры — заглушки (извлечения нет). Метрики на двух обучающих объектах (15 эталонных проверок
организаторов): **Precision 1.00, Recall 0.80, F1 0.89, ложных срабатываний 0**; страницы-доказательства по пяти
эталонным проверкам Новослободской совпадают с эталоном полностью; значения ПД / РД / ИД — 11 из 11. OCR сканов
(PaddleOCR + исправление латинских букв-двойников в русском тексте) на пилоте организаторов — **0.950 посимвольно,
строго** (порог ТЗ 0,95; без штрафа за двойники — 0.954; `python -m ml.ocr_eval --bench`). Все цифры и как они
получены — в CLAUDE.md, «Текущее состояние».

## Полезные команды

```bash
python -m ml.submission validate out/submission_OBJ-NOVOSLOBODSKAYA.json   # проверка ответа по схеме
python -m ml.eval out/submission_OBJ-TYUMENSKAYA-5-GOLD-SEED.json out/submission_OBJ-NOVOSLOBODSKAYA.json  # метрики
python -m ml.evidence_boxes out/submission_OBJ-NOVOSLOBODSKAYA.json --png boxes/   # картинки страниц с рамками
python -m ml.review_pdf OBJ-TYUMENSKAYA-5-GOLD-SEED IOS4-078:140                  # PDF-карточка кандидата
```

`python -m ml.concrete … compare` перезаписывает ответ только треком КР — итоговый ответ собирать через `ml.run`.
