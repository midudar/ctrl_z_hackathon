## 1. Суть в трёх фразах

1. «Инспектор ИИ» сверяет три стадии документации одной стройки — проект (ПД), рабочую документацию (РД) и
   исполнительную (ИД, акты о построенном) — по матрице из 132 параметров Мосгосстройнадзора.
2. Система **не выносит вердикт**. Она готовит **кандидатов в нарушения** с доказательствами: файл, страница,
   подсвеченный фрагмент, значения на каждой стадии. Решение принимает инспектор.
3. Главный принцип — **сначала точность**: на обучающих данных организаторов ни одного ложного срабатывания. Если
   система не уверена, она честно пишет «сравнить нельзя», а не выдумывает нарушение.

---

## 2. Задача, которую решаем

- Инспектор Мосгосстройнадзора проверяет, строят ли **так, как утверждено**. Для этого он сверяет:
  - **ПД** — проектную документацию: что обещали, прошла экспертизу;
  - **РД** — рабочую документацию: по ней строят, она дробится на десятки комплектов;
  - **ИД** — исполнительную документацию: акты освидетельствования скрытых работ, исполнительные схемы, почти всё — сканы.
- Объём огромный. Только у тестового объекта хакатона — **213 файлов и 16 078 страниц**, из них **8 864 страницы —
  сканы** без текста. Вручную сверить всё невозможно, нарушения теряются.
- Типичные нарушения: в РД занизили класс бетона или арматуры, уменьшили толщину плиты, убрали вытяжку из помещения,
  не сделали тёплые полы, заменили чугунные трубы канализации на пластиковые, «съели» полезную площадь в пользу
  технической.
- Матрица из **132 параметров** (Приложение 1 к ТЗ) говорит, что сверять, где это искать в каждой стадии и что
  считать нарушением (триггер). **106 параметров — критические** (нарушение → приостановка работ), 26 — существенные
  (предписание).

---

## 3. Принципы решения

1. **Правила матрицы, а не «чёрный ящик».** Размеченных нарушений у организаторов всего 10 — на этом нельзя честно
   обучить модель. Поэтому решение о расхождении принимают правила из матрицы: «нарушение — только понижение класса»,
   «только уменьшение толщины» и т. п. Готовые нейросети используются там, где они сильны, — для **чтения** сканов (OCR).
2. **Кандидат, а не вердикт.** ТЗ прямо требует: подтверждает нарушение инспектор. Система даёт ему кандидата и все
   доказательства.
3. **Сначала точность.** Ложное «нарушение» отнимает у инспектора время и подрывает доверие. При сомнении ставится
   «сравнить нельзя» с пояснением. Это законный ответ и по правилам оценки: он не штрафуется как ложный.
4. **Каждое утверждение — с доказательством:** файл, номер страницы, рамка фрагмента на странице и сам фрагмент текста.
5. **Только действующие редакции.** Сверять можно только с последней утверждённой версией документа. Система сама
   отбирает её среди корректировок.
6. **Честность в оценке.** Правила разрабатывались на обучающих объектах и на пилотных объектах организаторов.
   **Тестовый объект для подбора правил не использовался**, закрытая разметка организаторов не открывалась.

## 5. Как это работает: пайплайн

Готовый слайд — `handover/slides/slide_02_payplayn.png`. Пять этапов:

1. **Реестр и редакции.** Для каждого файла — стадия, раздел, шифр. Среди корректировок одного тома («КР1», «КР1-кор2»,
   «КР1-кор3») остаётся действующая. Номер редакции читается **с титульного листа**, имя файла — запасной вариант:
   у одного тома в имени «кор3», а на титуле «Корректировка №4». У тестового объекта исключено **38 устаревших томов
   ПД из 89**. Без этого доказательства ссылались бы на отменённые тома, а за ссылку на отменённый том балл не дают.
2. **Чтение страниц.** Где есть текстовый слой — берётся он: быстро и точно. Сканы ИД читаются в **два прохода**:
   сначала распознаётся только заголовок страницы и определяется её тип (акт, реестр, сертификат…), потом полностью
   распознаются только нужные страницы. Подписи на чертежах РД нарисованы линиями (шрифт CAD экспортирован контурами),
   поэтому их тоже приходится распознавать.
3. **Извлечение значений** по трекам:
   - конструкции (КР) — классы бетона и арматуры, толщины, сечения, сталь, отметка 0.000;
   - вентиляция (ОВ) — марки систем → помещения на планах;
   - архитектура (АР) — экспликации помещений;
   - водоотведение (ВК) — материал труб;
   - пожарные характеристики;
   - акты ИД.
4. **Сравнение по правилу матрицы** и **страховки:**
   - нет уверенности → «сравнить нельзя»;
   - понижение класса по сканам ставится только, если его показывают **не меньше двух актов**;
   - установку, «пропавшую» у помещения, но найденную в РД у соседнего, — не считаем пропажей.
5. **Ответ:** все 132 параметра. У каждого — метка, значения ПД / РД / ИД, страницы-доказательства с рамками,
   пояснение для инспектора. Плюс отчёт о целостности комплекта (дубли, временные файлы, нет раздела в РД).

Этапы независимы и перезапускаются по отдельности. Тяжёлое распознавание выполняется один раз и кэшируется по
контрольной сумме файла (SHA-256).

## 7. Результаты по объектам

### Тестовый объект — Речников ул. 7-7 (официальную оценку считают по нему)

141 строка ответа:
- **1 кандидат:** PZ-003 «Площади помещений, −1 этаж». «Техническое пространство» 408,3 → 293,2 м² в одном документе

  - класс бетона фундаментной плиты;
  - класс бетона плит перекрытий надземной части — сверен по всем трём стадиям, включая акты;

  - толщины фундаментной плиты, перекрытий и стен;
  - сечения пилонов и колонн, подземной и надземной части;
  - рабочая арматура;
  - класс пожарной опасности С0;
  - итог по площадям «Объект»;
  - трубы канализации К1 и К2;
  - огнестойкие кабели систем противопожарной защиты (FRLS);
  - светодиодное освещение;
  - огнестойкость дверей (EIS60).
- **32 «нет документа»:** в РД нет комплектов ОВ, СС, ТХ, ГСВ, ППР.
- **92 «сравнить нельзя»:** 85 — параметры без извлечения («не проверялось системой»), 7 — сравнили, но не уверены
  (значение только на одной стадии, сталь в РД частично слабее, в РД не найдено исполнение кабелей HF из ПД).

дал 8 кандидатов на обучающем объекте, на Речникове не работает: в его РД нет комплектов ОВ.

## 9. Распознавание сканов (OCR)

Готовый слайд — `slide_04_ocr.png`, график — `chart_ocr.png`.

**Как выбирали движок — замером, а не на глаз.** Взяли пилот OCR организаторов, из него 600 строк обучающих объектов,
для которых правильный текст известен из текстового слоя PDF. Мера — посимвольная точность (1 − CER), как в ТЗ.

| Движок | Точность строго (как выдал движок) | Строго + наша постобработка | Строк без единой ошибки |
|---|---|---|---|
| EasyOCR (был в начале) | 0,801 | 0,823 | 21% |
| Tesseract 5 | 0,929 | 0,931 | 57% |
| **PaddleOCR v5 (выбран)** | 0,947 | **0,950** | **66%** |

- **«Строго»** — латинская и кириллическая буквы одинакового начертания (A и А) считаются разными. Без этого штрафа
  PaddleOCR даёт 0,954.
- **Постобработка:** латинские буквы-двойники внутри русского текста переводятся в кириллицу («AKT» → «АКТ», оси
  «2/B» → «2/В»); обозначения вроде «B25», «A500C» не трогаются.
- **Проверка на деле:** 20 актов Новослободской, отрисованных как сканы. PaddleOCR даёт те же конструкцию, класс бетона,
  класс арматуры и дату, что текстовый слой, — **20 из 20** по каждому полю.
- **Скорость:** 1,8 с на страницу A4 на GPU.
- **Главная трудность** — курсивный шрифт чертежей: EasyOCR читал «Лист» как «hucm».

**Осторожно с цифрой 0,950:** она ровно на пороге ТЗ (0,95) и посчитана на 600 строках. Статистическая погрешность
такой оценки велика: 95%-интервал — примерно **от 0,93 до 0,97**. Формулировка — «на границе порога», а не «превышаем».

## 10. Исполнительная документация: 8 324 страницы сканов

Готовый слайд — `slide_05_skany_id.png`.

- ИД тестового объекта — **31 файл, 8 324 страницы**, почти всё — сканы. Акты сшиты в папки по ~300 страниц
  («ИД 7.7 Папка №12. 7 Этаж»).
- Сплошное распознавание — часы. Поэтому **два прохода:**
  1. **Заголовки.** Распознаётся только верхние 40% страницы в низком разрешении (120 dpi) — этого хватает, чтобы понять
     тип страницы: бланк акта, реестр приложений, документ о качестве бетона, сертификат, схема. Проверка на
     Новослободской (там у актов есть текстовый слой — эталон): **бланки актов найдены 226 из 226, ни одной чужой
     страницы.**
  2. **Полный OCR только нужного:** 910 страниц — бланки актов, реестры приложений и продолжения бланков.
- **Деление на акты:** сшитые папки разрезаются по началу бланка — **309 актов**. Проверка на Новослободской: 99 начал
  актов из 99, лишних нет.
- **Акт → конструкция:** по виду работ («Армирование 4 этажа: плита перекрытия…») акт относится к конструкции —
  **168 актов**. Классы бетона и арматуры из актов сверяются с РД.
- **Защита от ошибок распознавания:**
  - «понижение класса» по сканам ставится, только если его показывают **не меньше двух актов**;
  - из марки смеси «В30 П4 F200 W10» берётся только первый класс: OCR читает W10 как «В10»;
  - строки-перечни продукции завода («B7,5 … B60») пропускаются.
- Распознавание выполнено заранее на GPU (Google Colab, T4) и лежит в кэше образа. На стенде жюри оно не повторяется,
  поэтому прогон быстрый.

## 12. Метрики против порогов ТЗ — честно

Готовый слайд — `slide_07_metriki.png`. **Все цифры — на обучающих объектах** (15 эталонных проверок организаторов:
10 нарушений, 5 «нарушения нет»). Выборка маленькая: одно найденное или пропущенное нарушение двигает полноту на 0,10.

| Метрика (ТЗ 14.3) | Порог | У нас | |
|---|---|---|---|
| Precision (точность: доля верных среди наших кандидатов) | ≥ 0,90 | **1,00** | проходим |
| FPR (ложные на проверенных «нарушения нет») | ≤ 0,10 | **0,00** | проходим |
| Recall (полнота: доля найденных нарушений) | ≥ 0,80 | **0,80** | проходим, на границе |
| F1 | ≥ 0,85 | **0,89** | проходим |
| OCR, посимвольная точность, строго | ≥ 0,95 | **0,950** (без штрафа за двойники 0,954) | проходим, на границе |
| Точность ключевых полей | ≥ 0,90 | **1,00** (значения ПД / РД / ИД по эталону — 11 из 11; поля 20 актов-«сканов» × 4) | проходим |
| Локализация: файл и страница | ≥ 0,95 | **0,80** (на Новослободской — 5 из 5) | **не проходим** |
| Рамки фрагментов (bbox) | выдавать | 156 из 156 | есть |

**Пояснения для выступающего:**
- **Recall и F1 подняты 26.09** правилом чтения выносок по ГОСТ ([п. 13.3](#133-выноски-по-гост-подпись-на-полке-относится-к-тому-на-что-указывает-линия)).
  Было 0,70 и 0,82, стало 0,80 и 0,89. Ложных кандидатов при этом не появилось.
- **Локализация 0,80** считается по всем 10 нарушениям. Два пропущенных нарушения (012, 314) без страниц — отсюда
  0,80. Чтобы пройти 0,95, нужны все 10.
- **Главная оговорка:** официальную оценку организаторы считают по **закрытой разметке тестового объекта**. Там
  цифры будут другими, скорее всего ниже по полноте: система проверяет 19 параметров из 132, а какие нарушения
  заложены в тест, мы не знаем. Сильная сторона, которая, скорее всего, сохранится, — **точность и отсутствие ложных
  срабатываний**.
- Формулировка для слайда: «**На обучающих данных организаторов** проходим пороги точности, полноты и F1; локализация —
  0,80 при пороге 0,95». Не «проходим все пороги ТЗ».
- Порог «связка документов ≥ 0,95» (верные объект, стадия, шифр и редакция) отдельно **не измерялся**.

## 13. Инженерные находки, которыми можно гордиться

Истории «проблема → решение» для выступления или ответов на вопросы.

### 13.1. Подписи на чертежах нарисованы линиями

В рабочих чертежах вентиляции подписи систем («В2.7», «П2») в PDF — **не текст, а линии**: шрифт CAD экспортирован
контурами. Регулярные выражения находили 3 марки вместо 20. Решение — распознавание даже для «векторных» чертежей.

### 13.2. Слои CAD внутри PDF

PDF из CAD сохраняет **слои**: «ОВ-Архитектура», «Монолит», «…-Выноски». Стены и выноски берутся по имени слоя, а не
угадываются по толщине линий. Это убрало ошибки привязки подписей к помещениям: стены в РД нарисованы кусками по
90–96 pt и раньше не распознавались как стены.

### 13.3. Выноски по ГОСТ: подпись на полке относится к тому, на что указывает линия

Подпись установки часто стоит **над стеной** между двумя помещениями, а наклонная линия-выноска ведёт к установке
в соседнем помещении. Система относила подпись к ближайшему помещению — и ошибалась:
- «В3.1» над стеной 313 / 314 уходила в 313;
- «В17.13» над коридором 168 уходила в коридор, хотя линия ведёт к клапану в горячем цехе 189.

Решение по ГОСТ 2.316: если текст стоит **на полке**, от конца которой идёт **наклонная линия**, подпись относится к
помещению на конце линии. Итог: найдено нарушение в помещении 147, ушло ложное в 168, полнота 0,70 → 0,80, F1 0,82 → 0,89.
Ложных не появилось. Попутно исправилась привязка и в РД: шесть стояков в углу помещения 249 раньше «уходили» в
соседнее 202 за стеной.

### 13.4. Действующая редакция — с титульного листа

Рядом с томом лежат его корректировки («КР1», «КР1-кор2», «КР1-кор3»). Номер берётся с титула: у одного тома в имени
«кор3», а на титуле «Корректировка №4». У тестового объекта исключено 38 устаревших томов из 89, и доказательства
переехали с отменённого тома 2022 года на действующий 2025 года.

### 13.5. Экспликации помещений: таблица без таблицы

Экспликации на листах АР — это не таблицы PDF, а слова и линии сетки. Готовый поиск таблиц PyMuPDF работал 47 с на
страницу и рвал ячейки, поэтому написан свой разбор: строки режутся по линиям сетки, многострочные названия
склеиваются, наложенные значения сохраняются. Учтено, что:
- перенумерация помещений без смены назначения — справка, а не кандидат;
- разные этажи и секции не сопоставляются;
- сравнивается последняя ПД с последней РД.

На контрольной паре организаторов «без расхождений» (Полярная 17, 347 помещений) — **0 ложных кандидатов**.

### 13.6. Ловушки текста

- «Все конструкции из бетона В60, **кроме фундаментной плиты**» — упоминание есть, а речь о другом.
- «Ст. 6» в тексте — это статья, а не марка стали.
- «147,2 кН·м» — не толщина.
- «фотолюминесцентная эвакуационная система» — не люминесцентные лампы.

Каждая такая ловушка закрыта правилом и проверена на обучающих объектах.

## 14. Целостность комплекта документов

Кроме проектных решений система проверяет **сам комплект файлов**. Типы дефектов взяты из пилотной разметки
организаторов: там 37 из 48 записей — именно такие дефекты. Вероятно, за это дают 10 баллов технической оценки.

Что проверяется:
- пустые и битые файлы;
- временные файлы редакторов (`~$…`, `.bak`, `.log`), в том числе внутри архивов;
- PDF без текстового слоя;
- точные дубли внутри стадии, между стадиями и между объектами;
- раздел есть в ПД, но нет в РД;
- устаревшие и конфликтующие редакции;
- шифр в имени файла не совпадает с шифром на титуле;
- акт ссылается на проект, которого нет в пакете.

**Тестовый объект:**
- 6 временных файлов внутри архивов РД;
- у 13 из 31 PDF ИД нет текстового слоя;
- в ПД есть разделы ОВ и СС, а в РД их нет;
- 38 устаревших редакций ПД исключены из сравнения.

Для протокола это готовый раздел «Статус загрузки документов».

## 15. Техническая готовность

- **Одна команда** — `python -m ml.run <объект>` — даёт полный ответ на 132 параметра. Так же запускается
  Docker-образ.
- **Работает офлайн:** без интернета, без внешних API и облачных моделей (требование организаторов к стенду). Модели и
  распознанный текст лежат внутри образа.
- **Время:** 1–4 минуты на объект на процессоре обычного ноутбука, GPU не требуется. Стенд жюри — 1 × H100 80 ГБ,
  24 ядра.
- **Устойчивость:** треки независимы — если один упадёт, остальные отработают, ответ запишется всё равно.
- **Воспроизводимость:** при тех же документах ответ совпадает байт в байт.
- **Самопроверка:** ответ проверяется по схеме организаторов перед записью. Метрики пересчитываются одной командой по
  их эталону.
- **Честно:** Docker-образ описан, но на момент 26.09 ещё не собирался (на ноутбуке ML нет Docker) — это задача
  DevOps команды.

## 20. Что говорить и чего не говорить

**Говорить:**
- «кандидат в нарушения», «на решение инспектора»;
- «на обучающих данных организаторов»;
- «ни одного ложного срабатывания на эталоне»;
- «извлечение написано для 19 параметров, и их число растёт; остальные честно помечены „не проверялось“»;
- «модели не обучали — размеченных нарушений 10; решения принимают правила матрицы, нейросети читают сканы»;
- «работает офлайн, без облачных моделей».

**Не говорить:**
- «система выявляет нарушения» без слова «кандидаты»: вердикт выносит инспектор, это требование ТЗ;
- «проходим все пороги ТЗ»: локализация 0,80 не проходит, а метрики посчитаны не на тестовом объекте;
- «покрываем все 132 параметра»: в ответе все 132, но извлечение — для 14;
- «обучили модель»: не обучали;
- любые цифры «по тестовому объекту» как метрики: разметка теста закрыта, мы её не видели и не должны были видеть.

**Нельзя показывать:**
- материалы объекта **УНДМС (здание МВД)** из пилота организаторов: там сведения о бронировании. В наших слайдах их
  нет, в своих — не добавляйте;
- закрытую разметку организаторов: у нас её нет и не было.

## 21. Вопросы жюри и ответы

**Почему не нейросеть? Сейчас всё делают на LLM.**
Размеченных нарушений у организаторов 10 — обучать не на чем, а проверить качество LLM на таком эталоне нельзя.
Решение о нарушении должно быть объяснимым: «класс бетона в РД ниже, чем в ПД, вот обе страницы». Нейросети
используются там, где они сильнее правил, — для чтения сканов (PaddleOCR). Облачные модели на стенде запрещены.
Локальную визуальную модель как «второе мнение» можно поставить на H100 — это в планах.

**Как вы гарантируете, что не будет ложных нарушений?**
Гарантий нет, но система так устроена:
- нарушение ставится только по триггеру матрицы (понижение, уменьшение);
- при сомнении — «сравнить нельзя»;
- по сканам «понижение» — только если его показывают минимум два акта.

На эталоне организаторов — ноль ложных. На контрольной паре «без расхождений» (Полярная 17, 347 помещений) — ноль
кандидатов.

**Почему на тестовом объекте всего один кандидат?**
Почти всё, что система умеет сверять, там совпало: 13 параметров подтверждены с доказательствами. Трек вентиляции,
давший 8 кандидатов на обучающем объекте, на тесте не работает — в его РД нет вентиляции.

**Не подгоняли ли вы правила под тест?**
Нет. Правила разрабатывались на обучающих объектах и пилотных объектах организаторов, на тесте — только итоговый
прогон. Закрытую разметку не открывали: папки организатора запрещены правилами, и мы их не распаковывали.

**Точность OCR 0,95 — это честно?**
Замер по методике ТЗ (1 − CER) на пилоте организаторов, 600 строк с известным текстом, строгий режим. 0,950 — на
границе. Из трёх движков выбран лучший по замеру; на реальных актах поля читаются 20 из 20.

**Что будет с документом, который загрузили в плохом качестве?**
Если текста нет и распознать нельзя, параметр получает «сравнить нельзя» с пояснением, а в отчёте целостности —
«PDF без текстового слоя». Система не выдумывает значение.

**Как система понимает, какая версия документа действующая?**
Группирует файлы по шифру и читает номер корректировки с титульного листа. Сверка идёт только с последней редакцией,
устаревшие перечислены в отчёте.

**Как быстро работает?**
1–4 минуты на объект на процессоре ноутбука. Тяжёлое распознавание сканов (910 страниц) выполнено заранее на GPU —
1,8 с на страницу — и хранится в кэше по контрольной сумме файла.

**Как добавить новый параметр?**
Пишется извлечение значения (где искать — подсказывает матрица) и правило сравнения из триггера. Формат ответа не
меняется. Так за последние дни добавлены помещения и площади, сталь, трубы, кабели, освещение, мощность и огнестойкость дверей.

**Почему так много «сравнить нельзя»?**
Большинство — параметры, для которых извлечение ещё не написано. В ответе они отличимы: без доказательств и значений,
в интерфейсе — «не проверялось системой». Это честнее, чем ставить «нарушений нет» без проверки.

**Где требование ТЗ про Sentence-BERT?**
Пока не используется: извлечение на правилах надёжнее проверять на маленьком эталоне. Семантические якоря — в плане,
чтобы быстрее добавлять параметры.

**Работает ли без интернета?**
Да. Все модели и распознанный текст — внутри образа, внешних вызовов нет.

**Как вы находите место на странице, если лист повёрнут?**
Координаты пересчитываются с учётом поворота, CropBox и MediaBox. Проверено глазами на листах с поворотом 90° и 270°
и со сдвинутой видимой областью.

**Что с DWG-чертежами?**
У каждого комплекта РД есть PDF-версия (проверено на тестовом объекте), сверка идёт по PDF. DWG — вне текущего охвата.

**Что с протоколом по Приложению 2?**
ML отдаёт все данные для всех семи разделов: статус загрузки, статистику, недостающие документы, критические и
существенные кандидаты со значениями и страницами, подозрения. Протокол формирует сервис.

## 23. Как оценивают

**Судейская доска ЛЦТ — 20 баллов, проходной 12.**
- На качество моделей приходится около 8 баллов, остальное — функциональность, доказательность, техническая
  готовность и удобство.
- Неработающий прототип получает не больше 6 баллов и не допускается в финал.
- Отсюда: **доказательность** (страницы, рамки, фрагменты) и **работающий образ** стоят не меньше метрик — на них
  стоит делать акцент.

**Технический скоринг — 100 баллов** (по закрытой разметке тестового объекта):

| Компонент | Баллы |
|---|---|
| Находка нарушений (F1) | 60 |
| Локализация: точный файл и страница | 15 |
| Точность значений и статусов | 15 |
| Целостность документов и обработка разбиения | 10 |

- **При пропуске любой утверждённой критической контрольной точки итог не выше 59.** Критических параметров 106 из 132,
  поэтому это правило, скорее всего, сработает. Оно касается всех команд, но на презентации обещать высокий технический
  балл не стоит.
- Метрики публикуются отдельно по разделам. При недостижении любого порога ТЗ система формально не принимается,
  даже если сводная F1 выше.

## 24. Словарь

| Термин | Простыми словами |
|---|---|
| **ПД** | проектная документация: что обещали построить; прошла экспертизу |
| **РД** | рабочая документация: по ней строят; комплекты по маркам (АР — архитектура, КЖ — железобетон, ОВ — вентиляция, ВК — водопровод и канализация, ЭОМ — электрика) |
| **ИД** | исполнительная документация: акты о том, что построено |
| **АОСР** | акт освидетельствования скрытых работ: подтверждает, что работа выполнена и из каких материалов |
| **Матрица** | 132 параметра с правилами «что сверять и что считать нарушением» |
| **Триггер** | правило нарушения из матрицы: «понижение класса», «уменьшение толщины» |
| **Кандидат** | найденное расхождение с доказательствами; нарушением его делает инспектор |
| **Редакция, корректировка** | версия документа; сверять можно только с действующей |
| **OCR** | распознавание текста на картинке |
| **Текстовый слой** | текст внутри PDF, который можно выделить мышью; у сканов его нет |
| **Рамка (bbox)** | прямоугольник, которым подсвечен фрагмент на странице |
| **Экспликация** | таблица помещений на плане: номер, назначение, площадь |
| **Выноска** | линия от подписи на чертеже к элементу, который она обозначает |
| **Слои CAD** | группы линий в чертеже («стены», «выноски»), сохранившиеся в PDF |
| **Precision / Recall / F1** | точность (доля верных среди наших кандидатов) / полнота (доля найденных из всех нарушений) / их среднее |
| **FPR** | доля ложных срабатываний на проверенных «нарушения нет» |
| **Обучающие объекты** | Новослободская и Тюменская: по ним есть публичный эталон |
| **Тестовый объект** | Речников ул. 7-7: по нему оценивают, разметка закрыта |
