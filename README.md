# Инспектор ИИ

_Репозиторий команды `ctrl_z_hackathon` · ЛЦТ 2026, кейс № 10 «Мосстройнадзор»._

Сервис для Мосгосстройнадзора (ЛЦТ 2026, кейс № 10): сверяет три стадии документации объекта капитального
строительства — **ПД** (проектная, утверждена экспертизой), **РД** (рабочая, по ней строят) и **ИД** (исполнительная,
акты о том, что построено) — по матрице из 132 параметров и готовит протокол по образцу Приложения 2 к ТЗ.

Система **не выносит вердикт**: она находит **кандидатов в нарушения** и прикладывает доказательства — файл, страницу,
подсвеченный фрагмент, значения на каждой стадии. Нарушением запись становится только после решения инспектора.

![Карточка кандидата: значения ПД / РД / ИД, страницы-доказательства с подсветкой, решение в 1–3 клика](ml-service/docs/img/ui_review.png)

## Быстрый старт — Docker

Нужны Docker с Compose и ~4 ГБ на диске.

```bash
git clone https://github.com/midudar/ctrl_z_hackathon.git && cd ctrl_z_hackathon
cp .env.example .env
# 1) кэш распознанных страниц: архив inspector_ml_assets.zip из GitHub Releases → распаковать в ml-service/
#    (там появятся out/cache/ и models/easyocr/; без out/cache/ сборка воркера упадёт)
# 2) документы организаторов (необязательно): в .env указать PACKAGE_DOCS и PACKAGE_DATA —
#    папки 01_ДОКУМЕНТАЦИЯ и 02_ФОРМАТ_ДАННЫХ_И_ПРИМЕРЫ/data из пакета участника
docker compose up --build
```

Откройте http://localhost:8080 — вход `inspector` / `inspector`.

| Адрес | Что |
|---|---|
| http://localhost:8080 | интерфейс инспектора |
| http://localhost:8080/api/docs | Swagger UI, спецификация OpenAPI 3.0 — `backend/openapi.yaml` |
| http://localhost:8080/api/v1/metrics | метрики Prometheus |
| http://localhost:15672 | RabbitMQ (`inspector` / `inspector`) |

Если документы пакета подключены, при первом запуске появятся три объекта организаторов с готовым протоколом
(импортированы ответы ML из `ml-service/out/`); «Запустить проверку» пересчитывает объект заново. Без пакета — создайте
объект и загрузите PDF ПД, РД и ИД: проверка запустится сама.

## Быстрый старт — без Docker

Node.js ≥ 22.13 (проверено на 24) и Python 3.11+ (проверено на 3.12).

```bash
pip install -r ml-service/requirements-worker.txt
cd frontend && npm ci && npm run build && cd ..
cd backend && npm ci
PYTHON=python3 ML_ROOT=../ml-service PACKAGE_DOCS=/путь/01_ДОКУМЕНТАЦИЯ PACKAGE_DATA=/путь/02_ФОРМАТ_ДАННЫХ_И_ПРИМЕРЫ/data npm start
```

→ http://localhost:8080. RabbitMQ в этом режиме не нужен: backend сам запускает Python-воркер. На Windows вместо
`PYTHON=… npm start` — файл `backend/.env` с теми же переменными.

## Учётные записи стенда

| Логин / пароль | Роль | Может |
|---|---|---|
| `inspector` / `inspector` | Инспектор | загрузка, проверка, решения по кандидатам, финализация, протокол |
| `supervisor` / `supervisor` | Инспектор-супервизор | то же + отмена финализации, журнал аудита |
| `admin` / `admin` | Администратор | объекты, отмена финализации, журнал аудита, пользователи |
| `ml` / `ml` | ML-инженер | просмотр, полные журналы обработки, решения для дообучения |

Пароли задаются переменными `PASS_INSPECTOR`, `PASS_SUPERVISOR`, `PASS_ADMIN`, `PASS_ML` при первом запуске.

## Как это устроено

```
frontend (React) ──REST──▶ backend (Node.js: API, OpenAPI, роли, аудит, SQLite)
                              │ задача «проверить объект»          ▲ события: ход, готово
                              ▼                                    │
                          RabbitMQ ──▶ ML-воркер (Python) ── ml.run: 8 треков извлечения и сравнения
                                        └─ REST: картинки страниц, протокол PDF / DOCX
```

| Папка | Что |
|---|---|
| `frontend/` | интерфейс инспектора: дашборд объектов, загрузка, протокол, карточка кандидата, журнал аудита |
| `backend/` | REST API (`openapi.yaml`), БД, очередь, журнал аудита, данные протокола, автотесты (`npm test`) |
| `ml-service/` | ML-часть: пайплайн `ml.run`, воркер `ml/worker.py`, протокол `ml/protocol.py`, образ для стенда жюри (`Dockerfile`) и образ воркера (`Dockerfile.worker`); [README ML-части](ml-service/README.md) |
| `docker-compose.yml` | RabbitMQ + ML-воркер + backend с интерфейсом |

## Что проверено

- Автотесты backend: `cd backend && npm test` (11 тестов: вход и права, проверка запросов по OpenAPI, правила решений и
  финализации, журнал аудита, выгрузка протокола, перенос решений между версиями).
- Сквозные сценарии в браузере: верификация всех кандидатов и финализация; новый объект из загруженных файлов →
  кандидат с доказательствами на трёх стадиях; дозагрузка с переносом решения.
- Метрики ML на обучающих объектах: Precision 1.00, Recall 0.80, F1 0.89, FPR 0 (15 эталонных проверок организаторов).

Сборка Docker-образов и путь через RabbitMQ на машине разработки не проверялись (там нет Docker) — подробности в
документе «Сервис», раздел 12.
